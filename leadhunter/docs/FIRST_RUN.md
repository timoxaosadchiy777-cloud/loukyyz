# Чек-лист первого запуска

Пройдите сверху вниз сразу после деплоя. Занимает ~10 минут.
Если пункт не сходится — в конце каждого блока сказано, куда смотреть.

---

## A. Сразу после деплоя

- [ ] **Контейнер поднялся**

      docker compose ps

  Ожидается `Up` и через минуту `(healthy)`. Если `Restarting` — смотрите
  блок «Что означают строки в логе».

- [ ] **Конфигурация принята**

      docker compose logs | head -20

  В логе должны быть строки:

      Запуск LeadHunter…
      Администратор: OWNER_ID=<ваше число>
      SQLite подключена: /app/data/leadhunter.db
      Источники лидов: rss

  Если вместо этого «Бот не может стартовать» — там же перечислено, что
  именно поправить в `.env`.

- [ ] **`OWNER_ID` совпадает с вашим.** Сравните число в логе с тем, что
      прислал @userinfobot. Это самая частая ошибка первого запуска: при
      неверном ID `/admin` просто молчит.

- [ ] **Живость подтверждена**

      docker compose exec leadhunter python healthcheck.py

  Ожидается `OK`.

- [ ] **ИИ отвечает**

      docker compose exec leadhunter python check_ai.py

  Если нет — лиды всё равно будут приходить, но с пометкой «AI недоступен»
  и без готового отклика. Для продажи это критично, почините до клиентов.

---

## B. Проверка себя как пользователя

- [ ] `/start` в боте → открылось меню (не экран «нужен доступ»).
- [ ] `/admin` → открылась панель со статистикой.
- [ ] `/menu → 🔍 Проверить сейчас` → бот ответил (список либо «пока ничего»).

---

## C. Проверка на живом клиенте

Возьмите второй Telegram-аккаунт (или первого клиента):

- [ ] Клиент жмёт `/start` → видит описание и кнопку **📨 Запросить доступ**.
- [ ] Клиент жмёт кнопку → **вам** приходит заявка с двумя кнопками.
- [ ] Вы жмёте **✅ Выдать доступ** → клиенту приходит «🎉 Доступ открыт!».
- [ ] Клиент жмёт `/start` → запускается мастер из 4 шагов.
- [ ] Клиент проходит мастер → открывается меню с его фильтрами.

Если заявка не пришла вам — `OWNER_ID` неверен (см. блок A).

## D. Как понять, что лиды идут

Первые лиды появляются в течение **5–10 минут** после запуска
(`FEED_POLL_INTERVAL=300`, то есть опрос раз в 5 минут).

```bash
docker compose logs -f | grep -E "новых лидов|AI scoring|Доставлено"
```

Здоровая картина выглядит так:

```
RSS weworkremotely.com: новых лидов в очередь — 12
AI scoring lead 45231 (кандидатов: 2)
score=87
decision=send
Доставлено 2 из 2 получателей: rss:45231
```

Проверить по базе, что лиды реально сохраняются:

```bash
docker compose exec leadhunter python -c "
import sqlite3
db = sqlite3.connect('/app/data/leadhunter.db')
print('лидов в базе: ', db.execute('SELECT COUNT(*) FROM orders').fetchone()[0])
print('доставок:     ', db.execute('SELECT COUNT(*) FROM lead_deliveries').fetchone()[0])
print('с доступом:   ', db.execute('SELECT COUNT(*) FROM users WHERE paid_status=1').fetchone()[0])
"
```

То же самое в Telegram: `/admin → 📊 Статистика`.

## E. Что означают строки в логе

| Строка | Смысл | Действие |
|---|---|---|
| `Доставлено N из M получателей` | лид ушёл клиентам | всё хорошо |
| `не подходит никому из N получателей (ИИ не вызывался)` | фильтры отсекли лид до ИИ | норма, так экономятся деньги |
| `Отсеян по бюджету` | сумма ниже `min_budget` | норма |
| `ИИ отклонил` | оценка ниже `min_score` | норма; если отклоняет всё — снизьте порог в `settings.yaml` |
| `AI ERROR` / `AI недоступен` | ИИ не ответил | `check_ai.py`; лиды не теряются, приходят без отклика |
| `Источник 'rss' недоступен` | не установлена зависимость источника | пересоберите образ |
| `парсер упал — перезапуск через N c` | биржа недоступна или сменила вёрстку | бот работает дальше, источник вернётся сам |
| `заказы не распознаны … изменилась вёрстка` | Kwork поменял разметку | правьте селекторы в `parsers/kwork_extract.py` |
| `ответ подозрительно короткий` | блокировка или капча на бирже | обновите `KWORK_COOKIE` |
| `Бот не может стартовать` | ошибка в `.env` | там же перечислено что именно |

## F. Перед передачей клиентам

- [ ] `profile.md` отредактирован под ваш профиль (иначе ИИ оценивает наугад).
- [ ] `min_score` в `data/settings.yaml` вас устраивает (по умолчанию 60).
- [ ] Сделан бэкап чистой базы: `cp data/leadhunter.db ~/clean.db`.
- [ ] Проверено, что бот переживает перезагрузку сервера: `sudo reboot`,
      затем `docker compose ps` — контейнер должен подняться сам.
- [ ] Вы знаете, как отозвать доступ: `/revoke ID`.
