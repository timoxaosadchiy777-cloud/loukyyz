# LeadHunter — руководство владельца

Всё, что нужно, чтобы поднять бота на VPS и выдать доступ первым клиентам.
Технические детали здесь не нужны — только команды и что должно получиться.

---

## 1. Установка на VPS с нуля

Нужен сервер с **Ubuntu 24.04**, 2 ГБ RAM (4 ГБ, если ставите локальный ИИ).

```bash
ssh root@ВАШ_СЕРВЕР

git clone https://github.com/timoxaosadchiy777-cloud/loukyyz.git /opt/leadhunter
cd /opt/leadhunter/leadhunter

sudo bash deploy/install.sh          # Docker (рекомендуется)
# или
sudo bash deploy/install.sh systemd  # без Docker
```

Скрипт ставит Docker, создаёт пользователя, каталоги и `.env` из шаблона.
Запускать повторно безопасно.

**После установки скрипт напомнит заполнить `.env` — сделайте это до запуска**
(см. следующий раздел), затем:

```bash
docker compose up -d
```

---

## 2. Настройка `.env`

Откройте `/opt/leadhunter/leadhunter/.env`. Обязательных полей два:

| Поле | Что вписать | Где взять |
|---|---|---|
| `BOT_TOKEN` | токен бота | [@BotFather](https://t.me/BotFather) → `/newbot` |
| `OWNER_ID` | ваш Telegram ID | [@userinfobot](https://t.me/userinfobot) → пришлёт число |

> ⚠️ Без `OWNER_ID` бот **никого не пустит** и админ-панель будет недоступна.
> Проверьте, что вписали именно своё число, а не ID бота.

### ИИ — выберите один вариант

**Бесплатно, локально** (по умолчанию, нужно ~5 ГБ RAM):

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama serve &
ollama pull llama3.1:8b
```

**Или по API-ключу** — впишите в `.env` любой один:

```
OPENROUTER_API_KEY=...     # https://openrouter.ai/keys (есть бесплатные модели)
GROQ_API_KEY=...           # https://console.groq.com/keys
```

Проверить: `docker compose exec leadhunter python check_ai.py`

### Kwork (по желанию)

```
KWORK_ENABLED=true
KWORK_COOKIE=        # необязательно: без неё видна только публичная выдача
```

Куку берут так: залогиньтесь на Kwork в браузере → `F12` → вкладка **Network**
→ любой запрос → заголовок `Cookie` → скопируйте целиком.

### Профиль исполнителя

Отредактируйте `profile.md` — по нему ИИ решает, какие заказы подходят.
Правится на ходу, перезапуск не нужен.

## 3. Выдача доступа клиенту

Способ первый — **клиент сам просит**:

1. Клиент открывает бота и жмёт `/start`.
2. Видит описание и кнопку **📨 Запросить доступ**.
3. Вам приходит заявка с кнопками **✅ Выдать доступ** / **❌ Отклонить**.
4. Нажимаете «Выдать» — клиенту сразу приходит «🎉 Доступ открыт!».

Способ второй — **вы выдаёте заранее**, зная Telegram ID:

```
/grant 123456789
```

Работает, даже если клиент ещё ни разу не писал боту.

**Отозвать доступ** (клиент не оплатил следующий месяц):

```
/revoke 123456789
```

Настройки и сохранённые лиды при этом не теряются — при возобновлении
подписки всё вернётся на место.

## 4. Проверка работоспособности

```bash
cd /opt/leadhunter/leadhunter

docker compose ps                    # статус должен быть healthy
docker compose logs -f               # живой лог
docker compose exec leadhunter python healthcheck.py   # OK = бот жив
docker compose exec leadhunter python check_ai.py      # ИИ отвечает?
```

В Telegram: отправьте боту `/start` — должно открыться меню (вы админ, доступ
у вас безусловный). Затем `/admin` — откроется панель.

---

## 5. Команды администратора

| Команда | Что делает |
|---|---|
| `/admin` | панель: пользователи, заявки, статистика |
| `/grant ID` | выдать доступ |
| `/revoke ID` | отозвать доступ |
| `/users` | список пользователей текстом |
| `/menu` | ваша обычная панель (вы тоже получаете лиды) |
| `/help` | справка, которую видят клиенты |

В `/admin → 👥 Пользователи` доступ переключается тапом по строке.
На кнопке «📨 Заявки» показано число необработанных.

## 6. Обслуживание

**Обновление** (с бэкапом базы и автооткатом при неудаче):

```bash
sudo bash /opt/leadhunter/leadhunter/deploy/update.sh
```

**Бэкап вручную:**

```bash
cp /opt/leadhunter/leadhunter/data/leadhunter.db ~/backup-$(date +%F).db
```

**Оперативные настройки** — `data/settings.yaml`, правятся на ходу без
перезапуска: `min_score` (порог качества лида), `min_budget`, `enabled_sources`.

**Перезапуск:** `docker compose restart` · **Остановка:** `docker compose stop`

---

## 7. Если что-то не работает

| Симптом | Причина и что делать |
|---|---|
| Бот не отвечает на `/start` | Проверьте `BOT_TOKEN`. `docker compose logs \| head -20` |
| `/admin` молчит | `OWNER_ID` вписан неверно. В логе есть строка `Администратор: OWNER_ID=...` — сравните со своим |
| Лиды не приходят | Фильтры слишком узкие (`/menu → ⚙️ Настройки`) либо `min_score` высокий |
| В карточке «AI недоступен» | ИИ не отвечает. `check_ai.py` покажет причину. Лиды при этом не теряются |
| `readonly database` | `sudo chown -R 10001:10001 /opt/leadhunter/leadhunter/data` |
| Kwork ничего не находит | В логе будет причина: блокировка/капча или смена вёрстки. Бот продолжит работать |
