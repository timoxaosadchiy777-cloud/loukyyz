# 🎯 LeadHunter 2.0

Полуавтоматическая система поиска фриланс-заказов на **международных площадках** с
**AI Lead Scoring**. Собирает свежие лиды из RSS/Atom-фидов (Upwork saved-search
RSS, удалённые джоб-борды и любой RSS-источник), **оценивает каждый заказ через ИИ
по смыслу** (а не по ключевым словам), пишет профессиональный отклик и присылает
карточку в ваш **Telegram-бот** с оценкой, категорией и причиной. Дальше вы ведёте
заказ по мини-CRM прямо в чате.

```
RSS-фиды (Upwork RSS, джоб-борды, …)
        ↓
🤖 AI Lead Scoring  — модель оценивает заказ по смыслу и вашему profile.md
        ↓  score ≥ min_score и модель рекомендует → дальше
✍️  AI генерирует отклик (локальный Ollama — бесплатно, без ключей)
        ↓
📲 Telegram: карточка с AI Score, категорией, причиной, откликом
        ↓
🗂  CRM: Новый → Написал → Переговоры → Выиграл/Проиграл
        ↓
🗄  SQLite: дедупликация, история, оценки, воронка
```

Отбор заказов делает **исключительно ИИ** по смыслу заказа и содержимому
`profile.md`. Ключевые слова, whitelist/blacklist не используются. Бюджет —
единственный дешёвый предфильтр *до* обращения к модели (чтобы не тратить запросы
на заведомую мелочь).

## 🧱 Стек

- **Python 3.11+** · **asyncio**
- **feedparser** — чтение RSS/Atom-фидов (модульный список источников)
- **Локальный AI через Ollama** (`ai/llm.py` + `ai/providers/`) — бесплатно, без
  API-ключей; платные провайдеры опциональны (только если задан их ключ)
- **httpx** — async HTTP-клиент для AI-провайдеров
- **Aiogram 3.x** — доставка карточек, кнопка копирования и CRM-воронка
- **SQLite** (aiosqlite) — дедупликация, история, AI-оценки, CRM-статусы
- **PyYAML** — оперативные настройки, редактируемые на ходу

его можно править на ходу (см. ниже). Подходящие заказы приходят карточками в бот
с AI Score и готовым откликом.

## 🤖 AI Lead Scoring

По каждому новому заказу модель получает ваш `profile.md` и текст заказа и
возвращает строгий JSON:

```json
{"score": 93, "category": "Telegram Bot", "reason": "Прямо по специализации", "probability_of_sale": 70, "should_send": true}
```

- **score** — насколько заказ подходит именно вам (0..100), по смыслу.
- **category** — категория заказа («Telegram Bot», «Парсинг», «Дизайн», …).
- **reason** — короткое обоснование оценки.
- **probability_of_sale** — вероятность довести заказ до сделки (0..100).
- **should_send** — рекомендация показывать ли заказ.

Оценка учитывает описание заказа, `profile.md`, бюджет и тип клиента. В логах
виден весь ход: `AI scoring lead …`, `score=…`, `category=…`, `decision=send`.

**Решение о доставке:** заказ проходит, если модель рекомендует его
(`should_send = true`) и `score ≥ min_score`. Явный веток (`should_send = false`)
отклоняет заказ независимо от score.

Если модель недоступна (нет ключа, исчерпана квота, сбой) — LeadHunter **не теряет
лид и не откатывается к ключевым словам**: карточка приходит с пометкой
«AI Score: н/д — оцените вручную», а владелец получает алёрт.

### `profile.md` — ваш профиль

Это «портрет» исполнителя, по которому ИИ судит о заказах: специализация, опыт,
желательные и нежелательные проекты, минимальный бюджет, стиль общения,
предпочтения. Пишите живым текстом — модель понимает смысл сама, никаких стоп-слов.
Файл перечитывается автоматически: правьте на ходу, перезапуск не нужен.

### 🔍 Диагностика ИИ (если `AI Score: н/д`)

Если карточки приходят с `AI Score: н/д` — ни один провайдер не ответил. Причина
видна в логах и через отдельную команду:

```bash
python check_ai.py
```

Скрипт по каждому провайдеру покажет: настроен ли он, какую модель использует, и
сделает реальный тестовый вызов (`Status: OK / FAILED` + причина), а в конце — кто
станет основным. Те же причины бот пишет в лог и в карточку явно:

```
AI ERROR (provider=OpenRouter, score:…): лимит/квота исчерпаны (429)
AI: ответ через Groq (score:…) после сбоев: OpenRouter: лимит/квота исчерпаны (429)
```

Частые причины: `401/403` — неверный ключ; `402` — нужен платный план; `404` —
недоступная модель; `429` — исчерпан лимит. При любой из них роутер сам
переключается на следующего провайдера.

## ⚙️ Оперативные настройки (`settings.yaml`)

Меняются **без правки кода и без перезапуска** — файл перечитывается на следующем
заказе:

```yaml
# Минимальный AI Score (0..100): заказы ниже не доходят до Telegram.
min_score: 60
# Предфильтр по бюджету (USD) ДО обращения к ИИ. Лиды без явной суммы проходят.
min_budget: 50
# Активные источники. Пустой список [] = все. Значения: upwork, fiverr, rss
enabled_sources: [upwork, fiverr, rss]
```

Файл создаётся автоматически при первом запуске (шаблон — `settings.example.yaml`).
Неверные значения мягко заменяются дефолтами, битый YAML — не роняет бота.

## 📬 Карточка лида

Под карточкой — личные действия получателя:

```
📋 Скопировать отклик
❤️ Сохранить            ✍️ Изменить отклик      ❌ Отклонить
✉️ Написал  💬 Переговоры  ✅ Выиграл  ❌ Проиграл
```

- **✍️ Изменить отклик** — «🔄 Сгенерировать заново» (ИИ пишет новый вариант) или
  прислать свой текст сообщением.
- **❌ Отклонить** — лид уходит из работы, карточка сворачивается.

**Всё это персонально.** Сохранение, правка отклика и статус воронки пишутся в
доставку конкретного пользователя (`lead_deliveries`) и других получателей не
задевают: один и тот же лид ведут независимо несколько человек.

## 🔀 Fan-out: один лид → много пользователей

Ключевое ограничение — **ИИ вызывается один раз на лид, а не на получателя**.
Достигается двумя стадиями отбора вокруг единственного анализа:

```
новый лид
  ↓ дедуп по source+external_id
  ↓ получатели = OWNER_ID + все paid_status=1 (у каждого свои фильтры)
  ↓ СТАДИЯ 1 без ИИ: биржа + бюджет + слова в заголовке/описании
  ↓   никто не прошёл → ИИ не вызывается ВООБЩЕ
  ↓ ОДИН AI-анализ: score, категория, стек, суть заказа
  ↓ глобальный порог min_score из settings.yaml
  ↓ СТАДИЯ 2 без ИИ: + категория и стек от ИИ
  ↓   никто не прошёл → отклик не генерируется
  ↓ ОДИН отклик на лид
  ↓ каждому подошедшему: если ещё не получал → карточка
```

При 50 пользователях это **2 вызова модели на лид вместо 100**, а лид, который
не нужен никому, не стоит ни одного.

Категория, стек и суть — объективные признаки самого заказа, поэтому считаются
один раз и переиспользуются для всех. Отклик тоже один: `profile.md` общий, и
отдельный запрос на каждого дал бы дословно тот же текст. Каждому кладётся своя
копия — её можно переписать кнопкой ✍️, не задев остальных. Настоящая
персонализация черновика появится вместе с профилем у каждого пользователя.

Дедупликация — таблица `lead_deliveries`, PK `(telegram_id, order_id)`: один
пользователь получает один лид ровно один раз.

**Владелец** идёт первым в списке получателей, и фильтров у него обычно нет —
дефолтные пропускают всё, поэтому он получает лиды ровно как до fan-out.

## 👥 Пользователи и доступ

Доступ к боту выдаёт администратор — владелец `OWNER_ID` из `.env`.

| Кто | Доступ |
|---|---|
| Администратор (`OWNER_ID`) | всегда, отозвать нельзя |
| Пользователь с `paid_status = 1` | есть |
| Все остальные | нет: `/start` покажет их Telegram ID |
| Любой, если `OWNER_ID` не задан | есть (dev-режим, как раньше) |

Команды администратора (остальным бот на них не отвечает):

```
/grant 123456789    — выдать доступ
/revoke 123456789   — отобрать доступ
/users              — список пользователей
```

Выдавать доступ можно заранее, по одному Telegram ID: пользователю не обязательно
сначала писать боту. Он получит уведомление, когда доступ откроют или закроют.

Пользователи хранятся в таблице `users` (`telegram_id`, `username`, `paid_status`,
`created_at`). Таблица создаётся автоматически при старте — существующая база
и накопленные заказы не затрагиваются.

## 🧭 Онбординг и панель управления

При первом `/start` пользователь с доступом попадает в мастер настройки — четыре
шага на инлайн-кнопках:

```
Шаг 1/4  🌐 Биржи              выбор площадок (Kwork виден как «скоро»)
Шаг 2/4  🏷 Категории          что интересно
Шаг 3/4  🔑 Ключевые слова     пресеты + «✏️ Добавить свои» (ввод текстом)
Шаг 4/4  💰 Бюджет             минимальная сумма
```

Любой шаг можно пропустить: **пустой фильтр = без ограничения**. После «✅ Готово»
открывается панель, дальше `/start` и `/menu` ведут сразу в неё:

```
⚙️ Настройки        🔍 Проверить сейчас
⭐ Сохранённые лиды  🌐 Биржи
```

- **⚙️ Настройки** — правка любого фильтра теми же экранами, что в мастере.
- **🔍 Проверить сейчас** — подбор среди свежих лидов по твоим фильтрам.
- **⭐ Сохранённые лиды** — избранное; наполняется кнопкой ☆ под карточкой.
- **🌐 Биржи** — быстрое включение/выключение площадок.

Фильтры у каждого свои: таблица `user_settings`, по строке на `telegram_id`.
Глобальный `settings.yaml` пользовательских фильтров не задаёт — он остаётся
эксплуатационными настройками владельца (`min_score`, LLM).

### Как добавить новую биржу

Одна строка в `core/sources.py` — и площадка сама появляется в мастере, в меню
«Биржи» и в фильтрах:

```python
SOURCES = (
    ...
    Source("kwork", "🇷🇺 Kwork", available=False),  # available=False → «скоро»
)
```

Дальше остаётся написать парсер в `parsers/` (см. `parsers/base.py`) и снять
`available=False`. Списки площадок нигде не дублируются — `settings.yaml`
валидируется этим же реестром.

## 🧠 AI: локальный Ollama (бесплатно, без ключей)

По умолчанию LeadHunter работает на **локальном Ollama** — никаких API-ключей,
квот и платных сервисов. Провайдер задаётся в `settings.yaml`:

```yaml
llm:
  provider: ollama
  model: llama3.1:8b
  base_url: http://localhost:11434
```

**Установка (один раз):**

```bash
# 1) Установить Ollama: https://ollama.com/download
#    Windows — скачать установщик; macOS: brew install ollama
#    Linux:  curl -fsSL https://ollama.com/install.sh | sh

# 2) Запустить сервер (Windows-приложение стартует само)
ollama serve

# 3) Скачать модель (~4.7 GB)
ollama pull llama3.1:8b

# 4) Проверить
python check_ai.py        # ожидаем: Ollama → Status: OK
python main.py
```

Слабый ПК? Возьмите модель полегче: `ollama pull llama3.2:3b` и укажите её в
`settings.yaml`.

**Fallback:** `Ollama → ручной режим`. Если Ollama не запущен, лид не теряется —
карточка приходит с пометкой причины и без ИИ-текста, бот не падает и не зависает.
Платные провайдеры (OpenRouter / Groq / Gemini) подключаются в хвост цепочки
**только** если вы явно задали их ключ в `.env`; без ключей они не дёргаются вообще.

**Экономия:** отклик генерируется только для лидов, прошедших `min_score`.
Слабые лиды тратят один запрос (скоринг), а не два.

Каждый провайдер — это класс в `ai/providers/` с методом `generate(prompt) -> str`:

```
ai/providers/
  base.py         # контракт AIProvider + ProviderError
  openrouter.py   # опционально (только если задан ключ)
  groq.py         # опционально (только если задан ключ)
  ollama.py       # ОСНОВНОЙ: локальные модели, без ключей
  gemini.py       # крайний fallback
```

Добавить нового провайдера = написать класс с `generate(prompt)` и включить его в
`_build_providers` (`ai/llm.py`). Скоринг (`ai/scoring.py`) и генерация откликов
(`ai/responder.py`) не меняются — они ходят через роутер.

## 🛡️ Устойчивость

- **Ретраи LLM** — временные сбои (429/5xx/сеть) повторяются с экспоненциальной
  задержкой; постоянные (400/403) обрываются сразу.
- **Graceful failure** — при любой ошибке ИИ пайплайн не падает: скоринг отдаёт
  «неизвестно» (карточка уходит на ручную оценку), генерация отклика — заглушку.
- **Ошибка одного фида** не роняет остальные и логируется; владелец получает алёрт
  (с антиспам-троттлингом).
- **Дедупликация** — каждый лид проверяется в SQLite по (source, external_id).
- **Миграция БД** — новые колонки (AI Score, CRM) добавляются в существующую базу
  идемпотентно, без потери данных.
